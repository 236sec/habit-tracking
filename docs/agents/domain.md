# Domain docs

This is a single-context repo. Read root `GLOSSARY.md` and relevant ADRs in `docs/adr/` before exploring or changing a domain area.

If those files do not yet exist, proceed. The domain-modeling skill creates them when terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses, and tests. If a needed concept is absent, reconsider the term or note the gap for domain modeling.

Surface any conflict with an existing ADR explicitly.
